# Agent Note: 持久侧栏分区

Status: implemented
Archived: 2026-09-19

[English](2026-09-14-sidebar-sections.md) | 中文

## 问题

仅按项目分组无法组织跨多个目录的工作；为导航移动会话也不能改变其工具的执行位置。浏览器本地归类还会使不同页面显示互相冲突的项目列表。

## 决策

Workspace 注册表在版本 3 的领域中拥有单层自定义分区。分区分别保存有序项目标识和独立 Session 标识，项目位于 Session 之前。每个标识最多拥有一个显式分区位置。Session 归类不会改写其 Workspace 记账、工作目录、归档归属或日志。

分区编辑使用注册表写入队列和一次全局写入。持久布局版本同时涵盖默认项目顺序与自定义分区，包括回滚。基线、布局增量和命令回执共同携带该版本。Client 接纳较新版本，并在替换基线时隔离较早代次的响应。删除在记录删除提交时才对外可见；准备阶段的恢复标记不能提前发布项目移除。

分组侧栏只提交有效落点，Escape 或在外部松手会取消拖动。菜单支持无需拖动的移动和排序。保存被拒时保留已确认布局并显示重试。独立 Session 保持手动顺序；折叠状态保存在浏览器本地。单列表与搜索中每个 Session 只显示一次。

[Workspace 侧边栏顺序与折叠](2026-08-11-workspace-sidebar-order-and-folding.zh.md)继续拥有 Workspace 折叠和按记账活动排序的决策。[无标题 Ungrouped 段与可折叠默认区域](2026-09-18-headerless-ungrouped-run-and-default-area-folding.zh.md)拥有默认区域自身的折叠，以及不属于任何 Workspace 的会话行。本文拥有分组视图的拖动取消以及已提交分区和布局的传递规则。

## 考虑过的替代方案

**把 Session 移到另一个 Workspace。** 导航操作会改变工具执行假设，并破坏规范目录记账规则。

**在浏览器存储中保存分区。** 其他页面和重新启动的浏览器无法恢复同一组织结构。

**分别保存来源移除和目标插入。** 两次写入之间的失败可能丢失归类或暴露重复条目。

**在拖动结束时提交最后的悬停标记。** 取消跨分区拖动仍可能移动项目或会话。

## 后果

- 删除分区会把项目追加到默认区域，并使独立 Session 回到既有 Workspace 或“未分组”。删除项目会保留已独立归类的 Session。
- 较早的 Workspace 领域版本会明确报错，不提供迁移或自动数据清空。
- 分区控件不会增加模型指令或 Session 事件。

## 测试

注册表测试覆盖排序、唯一归类、无效锚点、写入失败、竞争编辑、重启恢复和版本拒绝。控制器与模型测试覆盖完整布局传递、旧回执和重连代次隔离。组件测试覆盖创建、折叠、移动、取消、重试以及唯一的单列表与搜索结果。无密钥 Web 场景驱动两个独立浏览器上下文和 Host 重启，渲染录制的 Session，并在打开它之前核验持久事件。
