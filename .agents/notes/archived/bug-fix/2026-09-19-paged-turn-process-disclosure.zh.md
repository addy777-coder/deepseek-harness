# Agent Note: 分页轮次过程折叠

Status: implemented
Archived: 2026-09-19

[English](2026-09-19-paged-turn-process-disclosure.md) | 中文

## 问题

长会话打开时只加载尾部一页，若过程折叠要求完整会话历史，已完成的思考与工具行就会持续展开，直到用户加载所有较早分页。已加载轮次可以独立于较早分页提供关闭状态与最终正文。部分窗口中的计数也无法可靠地描述整个轮次。

## 决策

Compact 模式按轮次折叠每个合格的已关闭轮次，不依赖会话是否仍有「加载更早」。最终正文保持可见，淡色耗时标签后的展开箭头控制此前的过程行和最终步骤中的推理。标签通过共享的本地化时长格式器显示日志中 `turn/start` 到 `turn/end` 的耗时。缺少任一时间戳时，标签显示「已思考」；Client 不会用首条已加载事件估算耗时。加载较早分页时，同一轮次与正文步骤的手动展开状态保持不变。

本决策仅取代 [Web 轮次过程折叠](../feature/2026-08-14-web-turn-process-folding.zh.md)中的完整历史要求与计数标签。该记录继续负责成员划分、运行中轮次的可见性、缺少正文时的行为、焦点保留、浏览器查找恢复与共享查看状态。[稳定的轮次过程排序](2026-08-26-stable-turn-process-order.zh.md)继续负责行的摆放。这些独立规则使两份较早记录均保留为活跃记录。

## 曾考虑的替代方案

**先加载所有分页再折叠。** 不采用，因为打开长会话需要先获取并渲染全部历史才能紧凑地显示正文。

**把首条已加载事件的时间当作开始时间。** 不采用，因为分页可能从轮次中途开始，会低估耗时。

**为不完整轮次保留计数摘要。** 不采用，因为较早调用或回复尚未加载时，可见计数容易被误认为完整总数。耗时标签只依赖日志中的起止时间，并明确处理时间不可用的状态。

## 后果

分页会话中的已关闭过程内容默认紧凑显示，用户无需加载较早历史即可手动展开。前插分页补齐缺失的轮次开始事件后，可以显示耗时而不改变展开状态。组件测试覆盖有耗时与无耗时的部分历史、新加载的较早轮次、最终正文可见性与手动展开；录制会话的浏览器快照覆盖本地化耗时控件及其展开内容。
