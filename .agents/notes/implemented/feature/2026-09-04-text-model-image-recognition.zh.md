# Agent Note: 文本模型使用持久图片识别上下文

Status: implemented

[English](2026-09-04-text-model-image-recognition.md) | 中文

## 问题

会话选择仅支持文本的模型后，持久图片历史仍可能有用。把每张图片替换成省略标记可以让提供方请求保持有效，却无法为该模型提供回答问题所需的图片信息。把图片发送给任意可用模型会隐式决定提供方、成本和数据披露。每次请求都重新分析图片还会增加延迟，并可能为同一张持久图片给出不一致的描述。

## 决策

**一个显式精确路由为纯文本模型提供图片识别。**实时 `image-recognition` 设置保存 `model: { provider, model } | null`。`null` 会关闭该功能。Models 页面只列出已解析 `inputModalities` 明确包含 `image` 的路由；它不会根据 id 推断能力，也不会消耗一次测试推理。设置、适配器与提供方目录可以独立变化，因此 Service Provider 会在每次辅助调用前再次验证已选路由。

**识别发生在主路由准备完成后、最终消息列表派生前。**Agent loop 在已认领输入持久化后暴露 `agent/request-context`。监听器返回带标识的用户角色上下文消息，loop 在记录请求 header 和冻结请求前追加这些消息。现有请求重建 invariant 因而覆盖生成的报告，且无需允许 `llm/stream` 监听器改写 loop 构造的请求。

**来源消息是复用单位。**识别器扫描当前会话 surface，查找包含图片但没有 `image-recognition` 来源记录的消息。它按持久顺序分析待处理消息，每次辅助调用只接收该消息的文本和有序图片。返回的 source 记录原消息 id、图片附件 id 与块路径，以及视觉路由。在新消息中重新附加相同字节会创建新批次，其关联文字可以提出不同问题。路由变更只影响未来批次，不会改写已完成历史。

**只有完整的事实报告会进入模型历史。**视觉请求不暴露工具或其他会话历史。其系统提示词要求提供可观察事实、空间关系和 OCR，并把图片中的指令当作引用数据。提供方失败、取消、工具调用、空文本或达到最大 token 都会拒绝本次准备。除非所有待处理批次都成功，否则监听器不会返回部分上下文；原始图片仍会持久保留，后续请求可以重试。

**所有图片生产方使用同一个回退决策。**浏览器提示词准入、ACP 输入、Subagent 后续消息、MCP 图片结果和 `read_image` 只有在 `ctx.imageRecognition` 解析出有效视觉路由时，才会接受纯文本目标。没有有效路由时，它们会在提交新图片内容前拒绝，并引导用户前往 Models 设置。支持图片的主路由会绕过识别。纯文本主路由保留持久图片，但其适配器投影会在生成报告旁发送省略占位符。

**Chat 隐藏内部报告但不会删除它。**识别上下文仍是会话 surface 上的普通 `user/message`，因此回放、压缩、Trajectory、导出和后续模型请求观察到同一个值。Chat 会话节点认领该 source 类型但不返回视图节点。展示方式无法改变请求重建。

## 考虑过的替代方案

**自动选择第一个可用视觉模型。**未采用，因为提供方选择会控制数据披露和成本。显式设置把这些决策留给用户。

**保存时探测模型能力。**未采用，因为 OpenAI 兼容列表没有定义模态，而真实图片请求会产生费用，并可能因无关的凭据、配额或网络问题失败。显式模型元数据是确定且可修正的。

**在 `llm/stream` 内改写消息。**未采用，因为 loop 构造的请求必须等于持久会话派生结果。新的 agent 扩展点会在请求构造前提交上下文。

**在会话或 DSH home 中按附件摘要缓存。**未采用，因为关联来源文本会改变重要细节，而且跨会话缓存会在说明其合理性的会话之外保留模型输出。

**识别失败后继续使用省略标记。**未采用，因为文本模型可能在没有收到图片证据时，把回答表现为基于图片。让轮次失败可以保留原始输入，并使重试保持显式。

## 验证

服务测试覆盖实时设置、目标验证、直接和嵌套图片收集、提示词隔离、完整输出执行、持久复用、失败保留和完全停稳的释放。真实 Loader 组合和 keyless `image-recognition-text-route` 录制固定完整的辅助与主请求顺序。Agent-loop 测试固定上下文顺序和请求重建。图片准入测试覆盖配置或未配置识别器时的浏览器、ACP、Subagent、MCP 与文件系统路径。客户端和 Web ARIA 测试固定显式模态写入、视觉标签、陈旧目标清除、受保护目标编辑、Chat 隐藏、Trajectory 保留和目录过滤。

## 后果

图片批次后的首次纯文本请求会为每条来源消息增加一次模型调用，并在主上下文中增加报告 token。后续请求会复用持久报告。报告可以跨重启保留，也可以随其描述的图片历史一起被压缩。辅助用量不进入 assistant 消息的每轮总计，因为该调用不是会话响应。即使会话模型属于另一个提供方，已配置提供方也会收到所选图片；Models 页面会在保存前说明这项披露。
